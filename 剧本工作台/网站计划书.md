# AI 短剧改编网站建设与上线计划书

**版本**　v1.0 评审稿  
**适用对象**　ayin、产品经理、前端、后端及总编剧工作流负责人  
**编制依据**　《短剧网站整改计划书 v1》及上一版《AI 短剧改编网站整改项目书》

## 一、建设目标

将现有短剧网站整改为一个以「总编剧」为入口的聊天式工作台。一比一复刻 ayin 在 Grok Bot 上的工作方式：拖文件、用白话交代任务、让总编剧复述、在卡片上拍板、随时补要求或查进度，最后在同一对话下载剧本。

首批用户是 ayin。她既是发起人，也是创作主审人和交付验收人。典型场景包括拿视频扒剧、上传国外底稿做改编、把国内短剧改编成面向海外的版本，以及用一句话开原创项目。续写场景中，用户可同时上传原文和已定稿的前 N 集，本轮从第 N+1 集写到全剧最后一集。

先做通功能再调整视觉。完成建设后，四类流程都须从聊天走到交付，待拍板时有卡可点，后台运行时照常收消息，旧项目可查看，锁定稿一字不动。

## 二、现状和改造重点

| 现状 | 根因 | 建设任务 |
|---|---|---|
| 有卡片没答时，文字发不出去 | 前端把聊天文字直接当成卡片答案。匹配失败后重复弹卡 | 文本统一走消息接口，服务端仅在意图明确时提交卡片答案 |
| 国外迭代上传后无响应 | 45 集案例被切成 46 份，串行调用 51 次，8 分 18 秒无进度，期间 9 条消息被拒绝。分析已就绪时也缺少启动入口 | 按处理额度拆批，聊天与生成解耦，收稿复述后接「开始分析」卡 |
| 扒剧入口错位，文件缺集号时无提示 | 分流卡与当前角色对话分属两个线程。前端未处理识别失败 | 项目使用同一会话，无法识别的文件进入集号补录卡 |
| 多数阶段上传附件无效 | 仅首次迭代收原稿接通附件 | 按流程、阶段和文件角色入档，归属不明时询问 |
| 总编剧无任务时承诺交付时间 | 回复缺少真实任务状态和估时依据 | 读取后台快照，说明在跑、等待、失败或无任务。没有可靠依据时明确说明 |
| 新建、上传和历史入口重复，分流后断链 | 多套页面各自维护，固定停点多数只有文字 | 收敛到统一聊天，逐一接通停点与执行动作，源码单份维护 |

## 三、网站结构和建设范围

| 位置 | 内容及操作 |
|---|---|
| 聊天首页 `/` | 登录后直达。支持新对话、上传材料、选择四类流程或继续历史项目 |
| 项目会话 `/p/:项目` | 一个项目一个会话。左栏列出项目、搜索、回收站和使用说明。项目按最近更新排序，区分等拍板、运行中、空闲或已交付 |
| 聊天主区 | 顶部显示项目名、流程类别、当前停点和「一键叫停」。消息区展示总编剧回复、其他角色汇报、卡片、原位更新的进度及下载文件。长消息可折叠，下方可发送文字和附件 |
| 项目右栏 | 可收起，展示步骤、产出、要求台账和运行任务，保留「详情」入口。手机端项目列表用抽屉，项目右栏用底部弹层 |
| 后台 `/admin` | 独立保留。内部模型、线路、用量和调试信息仅后台可见 |

**入口收敛。** 旧用户路由重定向到 `/`。街景、NPC 办公室、立绘、门、旧表单和店内页退出构建。旧代码归档，删除须经 ayin 批准。老项目仅做兼容读取，原有数据维持原样。旧详情能力的入口形式待拍板。

**交互规则。** 输入区支持 DOCX、XLSX、MP4、ZIP 和图片。附件上传完成后可发送。有卡片未答或后台运行时仍可发文字。卡片支持单步、多步和每步自由输入。推荐项排在第一位。扒剧模式每部剧都询问，两个模式均无默认。预览及下载保持当前停点。

**范围边界。** 本计划覆盖聊天、四类流程、历史项目、文件交付及项目管理改造。第三期做版本对比、定稿锁定、整批操作、选句批注、任务动效和项目面板增强。角色单聊及对外用户额度展示待定，视觉高保真调整后置。

## 四、业务流程

### 4.1 通用流程

1. **收需求。** 总编剧提示可直接拖文件。用户发材料和说明后，先用 1–4 条白话复述每份文件的用途、锁定范围、全剧集数、本轮范围、用户原话和甲方意见。用户可确认或补充。确定流程及项目归属后建档，附件和要求入确认单。模糊指令弹候选项目卡。
2. **协商与追加。** 总编剧主动指出材料里的矛盾，提供选项、推荐及依据。上传阶段和生成中均可追加要求，每条记入台账并回告生效范围。新要求在当前批次可更新的节点生效，必要时复查受影响的未确认稿。前后要求冲突时由用户裁定。
3. **执行和停点。** 开工前展示相应确认卡，说明派给谁、由谁核对。每个业务停点都可操作。后台环节每完成一步汇报一次。用户问进度时，回答当前集数、在做什么、在等谁、下一步、已知用费和有依据的预计时间。
4. **交回。** 用 3–5 条白话概述阶段结果，附 Word，并把待拍板事项做成卡片。最终剧本 Word 按梗概、人物小传、正文排列，并说明遗留问题。用户可先看、确认交付或提修改意见。

### 4.2 扒剧

接收 TikTok 导出表或视频 → 核对集数和时长，无法识别或冲突的集号由用户补录 → 选模式 → 确认开始 → 显示已完成集数与总集数 → 交付并停住。

快速模式按整集看写并抽查几集，详细模式按每秒一帧逐格看完再写。交付 ZIP 含繁体单集 Word 和简体全集 Word，全集开头附梗概、人物小传。交付卡支持先看、确认、重扒指定集和转迭代。只有用户主动选择转迭代才接入目标流程。

### 4.3 国外迭代国外

| 顺序 | 产物与停点 |
|---|---|
| 收稿和分析 | 复述、确认并建档。点「开始分析」后生成底稿、事件映射、错名清单和逐集情绪曲线。停在曲线确认及待定事项多步卡，处理对位口径、最高点、男女频、悬空点和矛盾数字等 |
| 四项配置 | 确认本轮范围、背景、规模与结局、补充与边界。确认前停住 |
| 主线及人物 | 提供 2–3 套主线和对手方案供单选或混搭。简化主线单另行确认，过「看得懂关」才开放通过。之后一并确认剧名、梗概和人物 |
| 细纲和正文 | 先出 10 集细纲并确认，分批完成后再确认全剧细纲。正文前 3 集逐集确认，随后整批写。用户说「通过，写完吧」等明确指令时，可放开后续正文逐集停点 |
| 审改和交付 | 自动走初审、裁定、返修、复核、精修、终复核。仅分诊需裁定、终复核未清零、三轮改不过时发卡。交付 Word 后停在交付卡 |

续写时，把前 N 集作为独立锁定稿保存，并只读注入生成上下文。新增内容仅覆盖第 N+1 集到全剧末集。生成、编辑、返修、精修和交付均保护锁定文字。以前 N 集在导出文件中的逐字比对为准。

### 4.4 国内迭代国外

沿用国外迭代的复述、原稿分析、四项配置、主线和对手方案、简化主线单、细纲、正文及交付。原稿分析加做「桥段出海四级诊断」，并按 **世界观 → 人设 → 替换要点** 逐道过门。每道门独立确认，全部通过才进入梗概和人物确认。三道门相对四项配置的顺序见建议。正文审改增加北美语感和美式幽默精修，并纳入终复核。

### 4.5 原创

一句话脑洞或补充设定 → 总编剧复述 → 点「开始推理」 → 完成前四层推理 → **停点 A**。该卡确认方向、开场 A/B/C、破局引擎、总集数和男女频。随后交设定集及细纲，每 10 集停下确认，末批一并确认。全部细纲通过后，点「开正文」。前 3 集逐集确认，之后整批写作和审改，最终交付 Word。

## 五、技术建设方案

| 模块 | 设计要点 |
|---|---|
| 前端 | 复用聊天接口、SSE 客户端、分片上传、卡片宿主及暂停控制。新增三栏布局、多步卡、文件卡和进度消息。按服务端返回的可用动作绘制按钮，刷新后恢复消息、卡片和任务 |
| 后端 | 复用迭代九步状态机、国内三道门、扒剧和原创接口。统一项目会话与附件路由。聊天写入与后台执行解耦，长输入保留原文并按额度拆分。待定事项结构化记录问题、选项、推荐及依据 |
| 状态机 | 分别记录项目阶段、任务状态和产物版本。项目支持待补料、待确认、执行中、暂停、可重试、待验收和已交付。推进前检查当前步骤、卡片版本、动作权限、费用授权。状态变化和待发事件一并保存 |
| 任务与锁定 | 计划按检查点执行，重试仅重跑失败步骤。台账保存原话、时间、作用范围、生效起点与版本，每次生成读取适用版本。锁定稿在编辑、批量写作和导出层均设保护 |
| 进度与权限 | 后台返回阶段、已完成数、总数、等待原因、可用动作及可空预计时间。SSE 按事件序号补发，断线无法补发时读取快照。文件下载检查项目权限和版本 |

**接口契约。** 发消息接收会话标识、客户端消息标识、文本和附件标识，持久化后确认。上传完成返回文件角色、可识别元数据和缺失项。答卡或控制任务提交项目、卡片、步骤、阶段版本及幂等键，重复提交只生效一次，过期操作返回当前状态。消息分为文本、角色汇报、卡片、进度和文件。失败响应含错误码、可读原因和可执行的下一步。

## 六、异常处理与红线

| 异常 | 处理 |
|---|---|
| 上传失败、文件损坏或缺集号 | 定位到文件，支持续传、重传、修改角色或补录集号，保留已成功附件 |
| 生成超时或结果为空 | 显示已完成进度。切小批次，在批准预算内按需换同类模型，只重试失败步骤 |
| 断线、过期卡或重复点开始 | 恢复消息和当前卡片，按版本和幂等键去重，防止重复派活和扣费 |
| 暂停或恢复 | 暂停请求后停止派发下一小步，说明在途工作及其结算状态。恢复从已确认检查点继续 |
| 审改无法自动完成或导出失败 | 审改问题弹裁定卡，保留版本。导出失败时从同一稿件版本重新导出 |
| 无任务、无可靠估时或达到费用上限 | 分别说明当前状态、预计时间是否可用和下一步。达到封顶或下一笔预计超限时停止新增付费任务并报告 |

发起付费、删除文件、对外发消息均须 ayin 预先批准。用户页面、接口返回、报错和导出不得暴露模型名、线路名、token 数、提示词及规范原文。内容保留完整，超长拆分，除剧本正文外单份不超过 5 万字。真实项目和材料不得用于测试。

## 七、里程碑、验收和费用

工期以已有能力可复用、前后端并行和验收及时反馈为前提，**合计估算 20–30 个工作日**。费用沿用原稿的功能包和验证用费口径，为**估算**。人力和长期运营费用另行测算。

| 分期与工期估算 | 网站交付 | 上线验收 | 费用估算及封顶 |
|---|---|---|---|
| 一期，8–12 个工作日 | 三栏聊天、旧入口切换、国外迭代国外及续写 | 登录直达。有卡或运行中仍可发送并获回复。原稿上传完成并进入对话后 30 秒内出现复述卡。各停点可操作，可在聊天内交付 Word。进度与后台一致，新增要求进入台账和后续产物，锁定稿逐字一致 | 0.80–1.50 美元，封顶 1.50 美元 |
| 二期，7–10 个工作日 | 扒剧、原创、国内迭代国外，接通扒剧转迭代 | 扒剧补集号、无默认选模式、完成 ZIP、按需重扒或转迭代。原创通过停点 A、细纲和正文确认并交 Word。国内迭代有四级诊断、三道门和北美语感与美式幽默精修。四条流程端到端通过 | 0.60–1.20 美元，封顶 1.20 美元 |
| 三期，5–8 个工作日 | 版本对比、定稿锁定、整批操作、选句批注、任务动效和项目面板增强 | 两版本差异可并排查看，定稿在所有编辑入口均受保护，选句批注只改对应位置，整批操作有逐项结果，面板和动效与真实后台状态一致 | 0.80–1.50 美元，封顶 1.50 美元 |

三期费用合计估算 **2.20–4.20 美元，三期上限合计 4.20 美元**。原稿先行修复封顶 0.80 美元，其归账方式待定。付费任务派发前校验已批准额度并预留费用，结算后对账，重试与换模型计入适用预算。

## 八、测试、上线和风险应对

1. **开发自测。** 每包在测试站验证，覆盖附件路由、流程跳转、阶段版本、幂等、权限、预算封顶、锁定、导出和 SSE 恢复。使用合成 45 集原稿复测首卡时延与运行期间发送。
2. **产品验收。** 用专用账号和合成材料检查移动端、待卡发消息、冲突处理、暂停恢复、缺集号和四类流程。检查实物 Word、ZIP、锁定稿比对和要求生效。用合成旧格式数据验证历史兼容。
3. **正式站放行。** 产品经理以自动化浏览器走通当期流程，逐步保留截图、网络请求、控制台错误和费用记录。日常测变更，上线前全量回归，二期起四条流程均纳入。同步扫描用户侧页面、接口、报错和导出，确认通过后请 ayin 试用。
4. **重点风险。** 原有九步流程回归通过复用执行层和阶段用例应对。长任务卡住通过拆小批次和可见进度应对。上下文冲突通过台账版本和人工裁定应对。预算越界通过派发前校验、在途预留和停单报告应对。

## 十、建议

- 把四类新项目和「之前的项目」放在一张分流卡。一期只与总编剧聊天，其他角色的汇报进入同一会话。
- 从项目右栏打开旧详情能力，可做项目内高级视图，旧独立入口按既定规则重定向。
- 「开始生成」作为开工确认。费用授权可按批次记录额度、覆盖动作和重试范围，弹卡频率待定。
- 续写的正文逐集停点按本轮前 3 个待写集计算。国内三道门紧接原稿分析，随后完成四项配置和主线方案。

## 十一、待拍板事项

1. 分流用一张卡还是两张卡？
2. 是否提供角色单聊，在哪一期上线、开放给哪些角色？
3. 旧详情如何呈现？若需删除已归档代码，哪些文件可删？
4. 「开始生成」每次都弹还是按费用阈值触发？批次授权和独立费用停点如何呈现？外部用户是否可见额度？
5. 是否认可三期顺序、工期估算和费用上限？先行修复的 0.80 美元如何归账？
6. 是否确认续写逐集停点的起算方式，以及国内三道门和四项配置的相对顺序？
