# 剧本工作台（总编剧 Story Studio）· 设计说明与细节理念

> 本文档完整记录「总编剧 · 剧本工作台」的产品理念、前后端架构、四类短剧业务流程、六大 AI 编剧工位调度、Skill 提示词插件机制、安全红线隔离，以及在真实中转接口与实战测试中打磨出的关键交互细节。

---

## 一、核心产品理念：像真人总编剧带队干活，而不是填一张复杂表单

很多 AI 写作工具最大的问题，是把创作者当成「提示词工程师」——一进页面就是几十个参数、模型下拉框、System Prompt 输入框和一堆看不懂的按钮。

**总编剧工作台的设计原点只有一句话：**
> **第一目标是让创作者（老板）完全不懵圈：一次只面对一件事，一步一步往前走，等待时知道后台在干嘛，出活了直接拿到能用的成稿。**

围绕这个原点，我们在交互上确立了五条核心细节原则：

1. **克制开场，绝不未战先乱**
   - 创作者刚拖入素材或刚说一句话时，不弹满屏的「建议 A/B/C」「采纳按钮」制造信息噪音。
   - 只用一两句大白话确认「收到了什么素材、准备走哪条流程、下一步点哪里」。
2. **一步一卡，单焦点推进**
   - 页面顶部提供清晰横向「流程进度条」，让创作者随时一眼定位当前处于第几步。
   - 同一时刻只呈现**一张**当前需要处理的卡片（如核对集号 → 选择模式 → 交付），避免上下同时堆叠两三张确认卡让人不知道先点哪一个。
   - 能合并的动作自动串联（例如第 1 步确认信息后自动连接工位并进入第 2 步，减少无意义的二次确认点击）。
3. **等待阶段完全透明**
   - 调用大模型中转接口或上传大视频往往需要数秒至数十秒；任何处理中状态都会在视觉焦点位置展示 **「⏳ 正在处理当前步骤 · 已用时 X 秒」** 的实时读秒条，并明确说明当前是哪个工位在做什么（如「正在上传视频」「扒剧工位正在按快速模式还原场次与台词」），消除「页面是不是卡死了」的焦虑。
4. **真人职场沟通口吻，该拍板才弹卡**
   - 系统对外只呈现「总编剧」与专项编剧角色，像正常员工向老板汇报工作一样沟通：遇到缺集号、需要选方向、发现剧情矛盾或需要过门禁时，才弹出清晰卡片请老板拍板；没有需要改动的地方就直接交付，不为了走流程而强行弹空卡片。
5. **所见即所得，成稿直接交付**
   - 所有流程的终点都是可直接下载使用的规范剧本交付包（按「故事梗概 → 人物小传 → 正文」结构组织），而非散落在聊天记录里的一堆零散 Markdown 碎片。

## 二、四类短剧业务流程设计

工作台完整覆盖海外/国内短剧生产的四条核心管线（定义于 `lib/types.ts` 与 `app/api/studio/route.ts`）：

| 流程标识 | 流程名称 | 适用场景 | 关键特色与业务规则 |
| :--- | :--- | :--- | :--- |
| `foreign` | **国外迭代国外** | 海外原稿二创、前 N 集已定稿续写 | 支持将前 N 集标记为 `locked`（只读锁定稿，一字不动），本轮从第 N+1 集续写至末集；过「简化主线单 · 看得懂关」后进细纲与正文；正文前 3 集逐集确认，支持「通过，写完吧」一键放开后续逐集停点。 |
| `domestic` | **国内迭代国外** | 国内爆款短剧出海北美本土化改编 | 在迭代流程基础上增加「桥段出海四级诊断」，并按 **第一道门（世界观落地）→ 第二道门（人设与声线本土化）→ 第三道门（桥段替换要点）** 逐道确认；终审阶段叠加北美语感与美式幽默精修。 |
| `transcribe` | **扒剧** | 分集视频 / 字幕 / 导出表还原剧本 | 自动从文件名识别明确集号（如 `第08集.mp4`、`EP12.mp4`、`剧名_7.mp4`），对模糊命名（如 `1-1.mp4`、`微信视频20261113.mp4`）绝不瞎猜，交由用户确认；必选「快速模式 / 详细模式」（不设默认）；还原后可选择主动转入 `foreign` 或 `domestic` 迭代（不自动强制跳转）。 |
| `original` | **原创** | 一句话脑洞从零孵化全剧 | 建档阶段不强制要求先填总集数；先跑前四层推理，在「停点 A」一张卡片上集中拍板故事方向、开场 A/B/C、破局引擎、总集数与男女频，再推进设定集、每 10 集细纲与正文审改。 |

## 三、前后端架构与关键技术细节

### 1. 目录与职责划分
- **创作者前台**：`app/page.tsx`（单页对话式工作台 + 步骤进度条 + 右侧项目手册/素材/产出/台账抽屉 + 实时读秒等待提示）
- **管理员控制台**：`app/admin/page.tsx`（多账号/邀请码管理、3 路 API 中转池配置、模型自动拉取、六大编剧工位模型绑定、Skill 提示词插件管理、调用审计日志）
- **核心服务端引擎**：`lib/server.ts`（持久化存储 `.data/studio-store.json`、对象存储 `.data/bucket/`、多路中转容灾调度、Skill 插件装配、客户端红线脱敏 `sanitizeForClient`）
- **API 路由层**：
  - `app/api/auth/route.ts`：专属 Key 登录、账号密码登录、凭邀请码注册激活
  - `app/api/studio/route.ts`：项目建档、对话、确认、连接工位、阶段卡片流转、提示词切换、转入迭代
  - `app/api/upload/route.ts`：多格式大文件上传（支持 raw binary 与 `multipart/form-data`）、集号自动识别、RFC 5987 中文文件名安全下载与剧本包导出
  - `app/api/admin/route.ts`：管理员鉴权接口、中转站测速与模型发现、工位路由保存、Skill 插件增删改查

### 2. 六大 AI 编剧工位与 API 中转调度（`lib/server.ts`）
系统将短剧生产拆分为六个专业工位，全面标准化为 **Gemini + GPT** 双模型族驱动（已彻底弃用 Claude）：
1. **01 · 总编剧（`director`）**：接待需求、复述要点、统筹推进与进度汇报
2. **02 · 原稿分析师（`analyst`）**：原稿五问、事件映射、错名排查、逐集情绪曲线与出海四级诊断
3. **03 · 扒剧小能手（`vision`）**：多模态看片还原分集场次、动作（▲）、台词与人名锚定
4. **04 · 故事策划师（`planner`）**：2–3 套主线与对手方案、简化主线单、国内三道门与原创前四层推理
5. **05 · 分集编剧（`writer`）**：分批细纲、正文前 3 集打磨、整批写作与锁集保护
6. **06 · 审稿官 & 剧本精修师（`polisher`）**：初审返修、北美语感与美式幽默精修、终复核与交付封装

**中转站工程适配细节：**
- **1 主 + 2 备中转池**：每个渠道支持配置主地址与 2 个备用中转地址，同时工位级别支持主通道 + 备选通道 1 + 备选通道 2 级联容灾。
- **三步自动发现模型**：后台选择模型族（Gemini / GPT）→ 自动探测中转站 `/v1/models` 与 `/api/pricing` → 点击模型胶囊一键选中并分配给六大工位。
- **多 Key 分组容错**：针对中转站常见「Key A 仅支持 GPT 分组、Key B 仅支持 Gemini 分组」的情况，遇到 `model_not_found` / `No available channel for model` 时自动轮换同渠道下一个 Key，而不盲目直接报错。
- **防误调工具保护**：部分中转代理默认注入 Agent 工具列表，导致模型在看片/写稿时返回空正文 + `tool_calls`。服务端对自定义中转站自动附加 `tool_choice: 'none'`，并在检测到 `finish_reason === 'tool_calls'` 时自动重试强制纯文本输出。
- **附件直传与文本抽取**：`vision` 工位自动将上传的 `.mp4/.mov/.webm` 视频以多模态格式直传给 Gemini 模型真正「看片扒剧」；同时内置轻量 ZIP/XML 解析，自动提取 `.docx`、`.xlsx`、`.srt`、`.txt`、`.md` 中的正文注入上下文。

### 3. 可热替换的 Skill 提示词插件系统
- **槽位拓扑**：`transcribe`（扒剧）为单槽位（`primary`）；`foreign`、`domestic`、`original` 为主/副双槽位（`primary` + `secondary`）。
- **优雅回退**：管理员可在 `/admin` 上传、热替换、停用或删除 `.md`/`.txt` 提示词插件；当项目未选插件或所选插件被停用/删除时，自动平滑回退到槽位默认插件或系统内置规则，绝不中断创作；创作者也可显式选择 `__builtin__` 跳过默认插件。

### 4. 多账号隔离与安全红线
- **数据隔离**：不同创作者账号的项目与素材严格按 `owner` 隔离，仅管理员在 `/admin` 具备全局项目总览与审计权限。
- **客户端零泄露红线（`sanitizeForClient`）**：
  - 创作者前台（`/`）统一只显示「**提示词**」名称与简介，绝不暴露 `.md/.txt` 原始正文或文件名。
  - 所有发往前端的 JSON、对话消息与导出文件均经过红线过滤器，自动剥离所有模型名（GPT/Gemini/Claude 等）、中转站 URL、API Key、token 统计字段与系统提示词指纹。
- **仓库安全**：推送脚本 `scripts/push-to-github.mjs` 自动排除 `.data/`、`.env*`、`node_modules/` 与 `.next/`，确保真实密钥与本地用户素材永不进入 GitHub 仓库。

## 四、质量验证体系

项目内置四套自动化验证脚本（可通过 `npm test` 一键执行）：
1. `tests/studio.test.mjs`：核心契约测试（总集数/锁定集数识别、文件名集号防误判、进度查询识别、客户端脱敏验证）。
2. `tests/e2e-verify.mjs`：多账号认证、邀请码注册、项目隔离与工位联调全链路测试。
3. `tests/skill-plugin-e2e.mjs`（33 项）：Skill 插件上传/替换/回退、200 MB 多格式上传、四大流程端到端与静态红线审计。
4. `tests/tier5-adversarial.mjs`（16 项）：白盒对抗测试（损坏 JSON 恢复、并发版本冲突 409、额度超限 402、多 Key 轮询与容灾审计、越权防护）。

## 五、下一阶段优化规划（基于最新实测反馈）

结合最新一次真实中转站扒剧实测反馈，下一轮迭代将重点落地以下四项体验升级：
1. **扒剧极简化**：移除模式选择卡中多余的「待拍板事项」与「补充意见」输入框；扒剧完成后如无异常直接交付，取消多余的第 3 步空确认卡。
2. **成稿直接 Word（`.docx`）下载**：扒剧产出不再在聊天气泡中吐出长篇 Markdown 原文，而是直接生成规范排版的 `.docx` 文件卡片供一键下载，气泡内仅用自然口吻汇报要点或异常。
3. **放开视频大小限制**：针对大体积视频提供无感大文件上传与服务端分段/抽帧适配，取消 28 MB 直传硬上限。
4. **输出全面提速**：精简工位提示词冗余、优先路由高吞吐低延迟模型通道，并支持多集并发处理与流式进度反馈。
