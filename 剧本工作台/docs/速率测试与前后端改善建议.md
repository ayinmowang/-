# 总编剧 · 剧本工作台 — 软件速率实测与前后端后续改善方案

**版本**　v2.1（可替换 `.md`/`.txt` 提示词插件体系与多类型大文件上传升级版）  
**测试环境**　Windows Server / Node.js v24.18.0 / Next.js 14.2.35 Production Build

## 一、 软件关键链路速率实测报告（R4）

本次针对插件体系改造后的核心接口、25 MB 视频大文件上传/下载、提示词目录加载与脱敏过滤、以及生产环境构建进行了真实基准测试（脚本：`tests/benchmark.mjs`）：

### 1.1 核心接口与文件处理耗时指标

| 测试链路 | 实测耗时 / 吞吐量 | 性能评级 | 说明 |
| --- | --- | --- | --- |
| **路由模块冷启动加载** (`auth`/`admin`/`studio`/`upload`) | **50.82 ms** | 极快 | 首次载入持久化存储与 6 大工位默认路由配置 |
| **专属 Key / 邀请码登录鉴权** (`POST /api/auth`) | **20.94 ms** | 极快 | 含会话生成与 `.data/studio-store.json` 落盘 |
| **后台上传 `.md` 提示词插件并设为默认** (`POST /api/admin`) | **9.75 ms** | 极快 | 含 UTF-8/BOM 校验、二进制拦截、同槽位默认互斥更新 |
| **前台拉取项目列表 + 脱敏「提示词」目录** (`GET /api/studio`) | **0.48 ms / 次**（20次均值） | 毫秒级 | 含 `buildCreatorPromptCatalog` 与全量 `sanitizeForClient` 递归脱敏 |
| **新建短剧项目并绑定主/副提示词槽位** (`POST /api/studio`) | **3.60 ms** | 毫秒级 | 含集数/锁集正则提取、总编剧初步建议生成与持久化 |
| **25 MB 高清分集视频上传** (`POST /api/upload`) | **31.93 ms**（**782.9 MB/s**） | 极快 | 移除无界内存 `Map` 后直接落盘 `.data/buckets/`，内存占用平稳 |
| **25 MB 视频素材流式读取下载** (`GET /api/upload?file=`) | **31.01 ms** | 极快 | 含权限隔离校验与 RFC 5987 UTF-8 文件名编码 |
| **完整剧本导出与脱敏合成** (`GET /api/upload?export=1`) | **0.56 ms** | 毫秒级 | 含梗概、人物小传、锁集保护声明、正文拼接与敏感词擦除 |
| **Next.js 14 生产构建** (`npm run build`) | **约 11.4 s** | 优秀 | 含 TypeScript 5.8.3 全量类型检查与 9 个静态/动态路由编译 |

### 1.2 实测发现的主要性能瓶颈与本次已修复项

1. **已修复瓶颈：大文件上传导致 Node 堆内存暴涨（OOM 风险）**
   - **原因**：原实现将所有上传文件的二进制 `ArrayBuffer` 无限缓存在进程内存 `memoryBucket` (`Map`) 中，且单文件限制死卡在 20 MB。
   - **本次优化**：将单文件上传上限提升至 **200 MB**（支持 `STUDIO_MAX_UPLOAD_MB` 环境变量动态调整），并为 `memoryBucket` 增加容量上限保护（仅缓存 `<= 2 MB` 的小文件且最多 16 项），大视频/压缩包直接流式落盘 `.data/buckets/`，实测 25 MB 视频上传仅需 `31.93 ms`。
2. **潜在瓶颈 A：`fs.writeFileSync` 全量 JSON 同步落盘**
   - 当前每次发消息、改状态或记审计日志都会触发 `flushPersistentStore()` 将整个 `.data/studio-store.json` 同步序列化写入磁盘。当历史项目超过 500 个或单项目对话超过 1000 轮时，单次 JSON 序列化耗时将从 `< 5 ms` 上升至 `50–150 ms`。
3. **潜在瓶颈 B：大模型长剧本生成采用同步 HTTP 等待而非流式 SSE**
   - 当前 `callStationLLM` 等待上游大模型完整返回后再一次性写回消息，当分集编剧整批生成 10 集细纲或 3 集正文（4000–8000 tokens）时，前端需等待 15–45 秒才有响应。

## 二、 基于项目立意的后续改善建议（R5）

围绕「**总编剧 · 剧本工作台**」的核心立意——**一比一复刻并超越 Grok Bot 的短剧总编剧对话式协作编辑室，让主审人（ayin）与编剧团队在一个会话内丝滑完成扒剧、出海改编（三道门）、海外续写（锁集一字不动）与原创起盘**——提出以下 **4 个后端改善方向** 与 **6 个前端改善方向**：

---

### （一） 后端改善方向（4 大方向）

#### 后端方向 1：从同步 JSON 文件存储升级为 SQLite (WAL 模式) / Cloudflare D1 双引擎 + 增量写入
* **现状痛点**：`.data/studio-store.json` 将账号、邀请码、提示词插件全文、所有项目消息流和审计日志放在同一个大 JSON 文件中全量读写，多人并发操作同一或不同项目时存在文件锁竞争与全量序列化开销。
* **落地建议**：
  1. 引入 `better-sqlite3`（开启 `PRAGMA journal_mode = WAL;`）作为本地/单机生产环境默认存储，保持与现有 Cloudflare D1 SQL 结构 100% 兼容。
  2. 将高频追加的 `messages`（对话流）、`requirements`（要求台账）和 `audit_logs`（审计日志）拆分为独立表，按游标分页查询，使单次消息写入延迟稳定在 `1 ms` 以内。

#### 后端方向 2：六大工位真实 SSE 流式输出（Server-Sent Events）与长任务后台队列解耦
* **现状痛点**：短剧分析（45–80 集原稿五问与情绪曲线）和整批正文生成耗时长，同步请求容易触发网关 60 秒超时；且《网站计划书》明确要求“聊天写入与后台执行解耦，生成中照常收消息”。
* **落地建议**：
  1. 新增 `GET /api/studio/stream?id=:projectId&cursor=:seq` SSE 推送端点，将 `callStationLLM` 改造为 `stream: true` 逐字推送，让创作者实时看到总编剧或分集编剧的打字生成过程。
  2. 引入基于检查点（Checkpoint）的异步任务执行器：将 60 集任务按每批 5–10 集拆分为子任务入队，每跑完一小步立即保存检查点并推送进度；若中途点击「一键叫停」或某小步超时，仅重跑失败小步，不丢已生成集数，不重复扣费。

#### 后端方向 3：服务端真实解析与生成标准排版 `.docx` Word 及繁简双版 `.zip` 交付包
* **现状痛点**：目前上传 `.docx` / `.xlsx` 仅作为二进制归档而未提取其中的剧本文本喂给大模型；且导出（`export=1`）输出的是 `.md` 文本，尚未生成带标准短剧剧本排版（场号、日/夜/内/外、▲动作、人物台词、标黄【待人工補寫】）的 `.docx` 与 `.zip`。
* **落地建议**：
  1. **上传解析层**：在 `/api/upload` 中集成轻量解析器（如 `mammoth` 提取 `.docx` 原稿/锁定稿正文、提取 `.srt` 字幕时间轴、读取 `.xlsx` TikTok 导出表集号与时长），自动把前 $N$ 集锁定稿原文存入 `project.lockedTextByEpisode`。
  2. **导出校验与打包层**：使用 `docx` + `jszip` 库在服务端直接生成《简体全集剧本（含梗概与人物小传）.docx》和《繁體單集劇本_第01-N集.docx》并打包为 `.zip`，同时在导出层对前 $N$ 集锁定稿执行**逐字 SHA-256 / 文本比对校验**，确保锁定稿一字不动。

#### 后端方向 4：提示词（Skill）插件的版本快照、变量模板注入与 A/B 效果评测
* **现状痛点**：虽然本次已实现 `.md`/`.txt` 主/副提示词插件上传与切换，但当管理员在后台更新某份 `.md` 提示词时，正在进行中的旧项目若直接热更新可能会与前序已确认的设定产生风格断层。
* **落地建议**：
  1. **版本快照锁定**：每次后台修改或替换 `.md` 插件时自动递增 `version` 并保留历史快照；项目建档或切换提示词时可选择“跟随最新”或“锁定当前提示词版本”。
  2. **结构化变量占位符**：支持在 `.md` 提示词中使用 `{{TOTAL_EPISODES}}`、`{{LOCKED_EPISODES}}`、`{{REQUIREMENTS_LEDGER}}`、`{{CAST_LOCK}}` 等动态变量，由后端 `resolveWorkflowSkillPrompts` 在调用对应工位时精准注入上下文位置，而非仅简单拼接在末尾。

### （二） 前端改善方向（6 大方向）

#### 前端方向 1：三期核心编辑室能力——双版本并排 Diff 对比与「选句批注局部重写」
* **项目立意契合点**：主审人（ayin）在审阅初稿与返修稿、或核对国内三道门前后的桥段替换时，最需要直观看到“改了哪几句”。
* **落地建议**：
  1. 在右侧「项目手册 → 产出」面板及阶段成果卡片中增加**「并排对比版本 (v1 vs v2)」**抽屉，高亮新增（绿）与删改（红）台词。
  2. 支持在剧本正文中直接鼠标划选某几句台词，弹出浮窗输入批注（如“把这句中式说教改成美式冷幽默”），仅针对选中段落发起局部精修，不动该集其余内容。

#### 前端方向 2：分集状态矩阵（Episode Grid）与锁定集可视化只读防呆
* **项目立意契合点**：短剧动辄 50–100 集，续写项目（如前 10 集锁定，写 11–62 集）和扒剧项目（核对每集视频与补写缺口）仅靠文字列表难以一眼看清全剧哪几集有问题。
* **落地建议**：
  1. 在右侧面板顶部增加 **1–N 集可视化方格矩阵**：`🔒 1–10 集（深灰锁定·只读保护）`、`✓ 11–20 集（绿色已确认）`、`◐ 21–30 集（蓝色生成中）`、`⚠ 第 32 集（橙色含【待人工補寫】缺口）`。
  2. 点击任意集数方格即可快速跳转到该集剧本正文或对应的扒剧视频素材。

#### 前端方向 3：扒剧视频内置轻量播放器与时间戳点击跳转（`00:41 【待人工補寫】` 联动）
* **项目立意契合点**：扒剧流程中，扒剧小能手会标出看不清的特写或字幕（如 `第 2 集 00:41 ▲【待人工補寫】`），目前编剧需要切回本地播放器找对应秒数。
* **落地建议**：
  1. 对已上传的 `.mp4`/`.mov` 视频素材，在右侧素材栏或补写校准卡片内嵌 HTML5 轻量视频预览器，并自动读取 `video.duration` 填入真实秒数。
  2. 将剧本中的时间戳（如 `[00:41]`）渲染为可点击胶囊，点击后直接将对应集数视频跳转到第 41 秒定格画面，实现“边看画面边填空校准”。

#### 前端方向 4：多步拍板卡的渐进式单步折叠体验与键盘快捷键流（Keyboard-First Studio）
* **项目立意契合点**：对照《设计审查.md》与《界面验收契约.md》，创作者每天高频拍板数十次，表单过长容易造成视觉疲劳。
* **落地建议**：
  1. 对包含 3 个以上字段的复杂卡片（如「原创停点 A」的 5 个字段、「国内三道门」的 3 道门），支持**单步渐进展开（1/3 → 2/3 → 3/3）**，已拍板子项折叠为顶部绿色摘要胶囊，随时可点「重改」。
  2. 增加编辑室级快捷键支持：`1` / `2` / `3` 快捷选中卡片上的推荐预设（`★ 推荐项`），`Cmd/Ctrl + Enter` 直接确认当前卡片，`Esc` 关闭任何抽屉或弹层。

#### 前端方向 5：大文件分片断点续传进度条与拖拽归类预检浮层
* **项目立意契合点**：本次已将上传上限放宽至 200 MB 并支持多格式素材，但当编剧一次性拖入 30 个分集视频或整包原稿+锁定稿+人物设定表时，需要更清晰的上传进度与角色归类体验。
* **落地建议**：
  1. 用 `XMLHttpRequest` (`upload.onprogress`) 替代普通 `fetch` 上传，在输入区展示每个文件的**实时百分比进度条、上传速率（MB/s）与单文件取消/重试按钮**。
  2. 当拖入多份文档时，弹出轻量的「素材角色快速核对条」，让编剧在上传瞬间即可一键勾选哪份是`🔒 前N集锁定稿`、哪份是`📄 原稿`、哪份是`📘 设定集`，避免上传后再逐一修改。

#### 前端方向 6：要求台账（Requirements Ledger）的标签筛选、作用范围可视化与冲突预警高亮
* **项目立意契合点**：“上传后、等卡时和生成中均可随时追加要求，每条记入台账并回告生效范围”是本工作台的核心灵魂。
* **落地建议**：
  1. 在右侧「要求」Tab 中，将原本纯文本堆叠的台账升级为带结构化徽章的卡片流：区分 `🌐 全剧适用`、`🔒 锁集保护规则`、`🎬 第 11 集起生效`、`✨ 采纳自总编剧建议`。
  2. 支持在台账面板直接暂停/撤回某条尚未生效的口头要求，并在总编剧检测到新要求与前序要求矛盾时，在台账对应条目上显示醒目的黄色 `⚡ 待裁定冲突` 标记。
