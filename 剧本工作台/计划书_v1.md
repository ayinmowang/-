# 短剧网站整改计划书 v1

- 2026-11-13（北京时间）｜产品经理起草，后续交外部 AI 优化补充
- 本文已去掉密钥、服务器地址、账号和模型线路名

## 一、背景与目标

**网站是什么**：一个 AI 短剧编剧网站。用户上传原剧材料或给一个脑洞，由 AI 编剧团队完成扒剧、改编、原创，最后交付 Word 剧本。团队角色有总编剧、扒剧小能手、原稿分析师、分集编剧、审稿官、台词精修师、原创负责人。

**现在的问题**：11-13 晚上线后，ayin 实测四个地方都用不了。她的评价是「完全用不了」「四不像」「重复的东西太多，光建档案就好几种方式」。

**ayin 的原话要求**：
1. 「你再不行按照 grok bot 去设计不就好了，页面啥的，最能一比一复刻我的流程和逻辑，后期再调页面」
2. 「街道啥的不方便都不用了，我先让功能实现是最重要的」
3. 整体感觉要像「我跟总编剧在 bot 上面这种感觉，有来有回，同时他还会提建议、弹卡片」
4. 上传阶段要有地方随时告诉总编剧补充要求，比如「前几集已锁定，只续写后面」

**目标**：
- 登录后直接进一个仿聊天机器人的页面。
- 四类流程（扒剧、国外迭代国外、国内迭代国外、原创）全部在这一个聊天里跑完。
- 总编剧主动复述、提建议、弹卡片，如实汇报进度。
- 先做通功能，视觉以后再调。

## 二、现状与问题清单

### 2.1 今晚实测的 5 个问题和根因

| # | 现象 | 根因 | 是否这次上线引起 |
|---|---|---|---|
| 1 | 办公室里打字发不出 | 有没答的卡片时，前端把输入的文字当作「回答卡片」提交，没走发消息接口。后端匹配不上关键词，就再补一张一模一样的卡。用户原话不显示，也没有回复 | 前端老问题 |
| 2 | 国外迭代国外上传原稿后完全没反应 | ① 45 集原稿进办公室拆批时，公共拆批函数被提速版改成「每批恰好一集」，一条消息拆成 46 份，串行调用模型 51 次，卡了 8 分 18 秒，中间没有任何进度。这期间她又发了 9 条消息，都被「正在回复上一条」(409) 挡回。② 后端其实已经就绪，可以「开始分析原剧」，但办公室只在国内三道门出现时才画确认按钮，按钮没画出来。③ 办公室上传原稿后，不会接着启动分析 | ① 是这次上线引起的；②③ 是一直没做的衔接 |
| 3 | 扒剧用不了 | 文件名叫「1-1.mp4」「微信视频…mp4」，认不出集号，接口报 400 EPISODE_NUMBER_REQUIRED，页面没有任何提示。另外从办公室进门时，页面停在扒剧小能手的线程，选流程的卡片却在总编剧的线程里，所以选不到扒剧 | 老问题 |
| 4 | 对话里上传文件不起作用 | 附件只有在「迭代项目、原稿阶段、还没有原稿」这一种情况下才交给流程。扒剧、原创和其他阶段都忽略附件 | 老问题 |
| 5 | 问「啥时候给我答复」，回答是「今天」 | 总编剧回答时拿不到后台真实状态（有没有任务在跑、第几集、预计时间、卡在哪），也没有「不许编时间」的约束。当时根本没有任务在跑，这个时间是模型编的 | 老问题 |

### 2.2 结构性问题

- **入口重复**。「新建项目」有 6 套入口：
  - 街景弹窗
  - 两个表单式新建页
  - 办公室卡片
  - 两个旧店内页

  「上传原稿」有 3 套，「看之前的项目」有 4 处。
- **主线断开**。办公室只做了分流：选完流程、建好项目就停住了，没有接到后台任何一条真正干活的流程。能跑通的旧表单页又被藏了起来。结果两套都用不顺。
- **停点不弹卡**。系统定了 12 个写死的停点，但除了「三轮改不过」和国内三道门，其余停点都只显示几个字，没有按钮，也没有卡片。
- **国内、国外分不清**。表单页新建项目时不带「国内/国外」这个类型。
- **原创无处可去**。新前端没有原创页面。
- **旧代码大量残留**。源码有两份，还有大量备份副本和死代码。

## 三、她的真实工作流

以下来自她和总编剧在聊天机器人上的真实合作记录，主要是 11-13 的两部剧。

### 3.1 通用骨架

1. **开头**：她拖进文件（docx、xlsx 或视频），写一段大白话交代：哪些集已锁定、全剧几集、这次做哪几集、文件 1 和文件 2 各是什么，最后说「复述一遍给我」。
2. **复述**：总编剧先按 1–4 条复述它的理解，问「对不对」，不直接开干。
3. **分流**：弹卡片，选新项目（四类之一）还是之前的项目。
4. **补料**：她陆续补发甲方意见、改编总要求原文，或者「整个剧是 62 集记得」。总编剧每条都回「记下了，写进确认单」。前后冲突时马上弹卡让她裁定。
5. **建档**：总编剧建好项目和确认单，同时报告查资料时发现的问题，比如「反派第 9 集已被捕，后面要换对手」。
6. **派活**：说明谁在做什么、做完先由谁核对。
7. **追问**：她问「咋样了」，总编剧按真实状态回答：在等谁、卡在哪、有没有花钱、下一步是什么。
8. **交回**：先用 3–5 条白话讲结论，附上 Word，再说「下面有 N 件事要你定，推荐的放第一个」，弹一张多步卡。
9. **拍板**：她点选项，或者在卡里自己打字，比如「美国都市，不要校园元素了」。
10. **中途加要求**：比如「加点爱情线和日常线」。总编剧马上补给正在写的这一批，并写进确认单。
11. **放开停点**：她说「好，通过，写完吧」，后面的逐集停点就放开，整批写到底。
12. **后台环节**：审稿、返修、精修、复核自动跑，每个环节只用白话汇报一次。
13. **交付**：一律用 Word，顺序是梗概 → 人物小传 → 正文，并说明还剩哪些小问题。
14. **指令模糊**：比如「继续写那个吧」。总编剧不猜，弹卡列出候选项目让她选。

### 3.2 四类流程

- **扒剧**：
  1. 交 TikTok 导出表或视频。
  2. 确认素材是几集、多长。
  3. 弹卡选快速模式（看整集写，抽查几集）或详细模式（每秒一帧逐格看完再写）。没有默认模式，每部剧都要问。
  4. 交付繁体单集 Word 和简体全集 Word 的压缩包，全集开头带梗概和人物小传。
  5. **停**，等她确认。扒剧不自动进迭代，她要迭代时再转。
- **国外迭代国外**：
  1. 复述并建档。
  2. 原稿分析：底稿、事件映射、错名、逐集情绪曲线。**停**，弹多步卡问待定事项（对位口径、最高点、男女频、悬空点、矛盾数字）。
  3. 四项配置：本轮范围、背景、规模与结局、补充与边界。**停**。
  4. 主线和对手方案出 2–3 套。**停**，她挑一套或混搭。
  5. 简化主线单，必须过「看得懂关」。**停**。
  6. 梗概人物，连同剧名一起定。**停**。
  7. 细纲先出 10 集，**停**；之后分批写完，全剧再**停**一次。
  8. 正文前 3 集逐集停。
  9. 之后整批写，再走初审 → 裁定 → 返修 → 复核 → 精修 → 终复核。
  10. 交付 Word，**停**。

  续写特例：她交来前 N 集锁定稿（一字不动）和原文，本轮只写第 N+1 集到最后一集。
- **国内迭代国外**：和国外迭代国外一样，但分析里多一项「桥段出海四级诊断」。之后逐道过三道门：世界观 → 人设 → 替换要点，再接梗概和后续步骤。正文后多一步北美语感和美式幽默精修。
- **原创**：
  1. 她给一句话脑洞。
  2. AI 推理前四层。**停点 A**：用一张卡定方向、开场 A/B/C、破局引擎、总集数、男女频。
  3. 设定集加细纲，每 10 集停一次。
  4. 细纲全部确认后才开正文。正文前 3 集逐集停，之后整批走。
  5. 交付 Word。

## 四、新产品形态

### 4.1 唯一入口

登录后，`/` 就是聊天页；`/p/:项目` 直接打开某个项目。其他旧路由全部重定向到 `/`。后台 `/admin` 单独保留。

### 4.2 页面布局（仿聊天机器人）

- **左栏**：
  - 「＋新对话」和搜索
  - 「我的项目」按最近更新排序，状态点分三种：● 等你拍板、◐ 后台在跑、○ 空闲或已交付
  - 回收站、使用说明
- **中间**：
  - 顶部显示项目名、流程类型、当前停点，以及「一键叫停」
  - 消息流里有：总编剧的白话回复（长文可折叠）、其他角色的汇报（小头像加名字，原样插入）、卡片（单步或多步，推荐项排第一、每步都能打字）、进度消息（原地刷新：第几集/共几集、在做哪一步、预计还要多久）、文件卡（Word 或压缩包，点了就下载）
  - 底部输入框：能打字，能加附件（docx、xlsx、mp4、zip、图片）。上传没完成时不能发送。有卡片没答时照样能发送，由后端判断这句话是不是在答卡
- **右栏**（可收起）：
  - 步骤条
  - 产出文件
  - 「我加的要求」台账
  - 当前在跑的任务

  原来的旧详情页降级成这里的「详情」链接。
- **手机端**：左栏改成抽屉，右栏改成底部弹层。

### 4.3 对话脚本要点

- **通用开头**：总编剧先说「有什么要做的？可以直接把文件拖进来」，同时弹分流卡。她发了文件和说明，就先复述，再弹「对 / 不对，我补充」。确认后建项目、把附件归档、把要求原文写进台账。
- **扒剧**：
  1. 收素材时，有认不出集号的文件就弹卡让她选第几集。
  2. 弹卡选模式。
  3. 弹「确认开始」卡。
  4. 跑的过程中显示进度消息。
  5. 跑完弹交付卡：先看 / 确认交付 / 转迭代（国外或国内）/ 重扒某几集。
- **国外迭代国外**：
  1. 复述并建档。
  2. 弹「开始分析」卡。
  3. 分析交回后弹待定事项多步卡和曲线确认。
  4. 四项配置多步卡。
  5. 主线方案 2–3 选 1。
  6. 主线单：没过「看得懂关」就不能确认，只能提修改意见或重新生成。
  7. 梗概人物和剧名卡。
  8. 细纲首批卡，之后是全剧细纲卡。
  9. 正文逐集卡；她说「写完吧」就放开后面的停点。
  10. 整批审改阶段只做白话汇报，只在出现分诊、终复核没清零、三轮改不过时弹卡。
  11. 交付卡。
- **国内迭代国外**：和上面一样，分析后依次弹三道门卡。
- **原创**：
  1. 收脑洞，弹「开始推理」卡。
  2. 停点 A 多步卡。
  3. 每 10 集细纲一张「继续 / 修改」卡。
  4. 弹「开正文」卡。
  5. 前 3 集逐集卡。
  6. 整批阶段做白话汇报。
  7. 交付卡。

### 4.4 卡片清单（文案照真实卡片来，★ 为推荐项）

| 卡片 | 选项 |
|---|---|
| 分流 | ★新项目·国外迭代国外 / 国内迭代国外 / 扒剧 / 原创 / 之前的项目 |
| 复述确认 | ★对，开始 / 不对，我补充 |
| 要求冲突（例：「女主变瘦这条按哪种写？」） | ★逐渐变瘦，但不是逆袭的原因 / 写成明线爽点 / 不写 |
| 分析待定事项（多步，例：「情绪对位定 5 件事」） | 对位口径、最高点、首集怎么接、结局情绪等 |
| 四项配置（多步） | 本轮范围 / 背景 / 结局 / 其余照默认 |
| 主线方案 | ★方案 A / B / C / A 为主掺 B |
| 梗概人物 | ★定稿，写细纲 / 先看文件；剧名二选一 |
| 细纲 | ★通过，继续写后面 / 先加强某几集 / 先看文件 / 要 Word 版 |
| 正文单集 | ★通过，写下一集 / 我有修改意见 |
| 扒剧模式 | 快速 / 详细（不设默认） |
| 缺素材 | ★我发表格或视频 / 直接发剧本 / 先放一放 |
| 模糊指令 | 列出候选项目 / 开新原创 |
| 交付 | ★我先看 / 通过并锁定 / 有修改意见 |
| 开始生成 | ★开始 / 先不（代替「花钱前先问」） |

## 五、前后端改动清单

### 5.1 后端缺口（G 编号）

- **G1** 一个项目一个会话，各角色的汇报都进同一条消息流。
- **G2** 有卡片时，文字一律当普通消息，由后端判断是否在答卡；判断不了就正常回复。（第一批在做）
- **G3** 新增「复述确认」步骤：输出结构化复述（文件角色、锁定范围、全剧集数、本轮范围、要求原文、甲方意见）。
- **G4** 分流建完项目后，接上对应流程的第一步。
- **G5** 附件按项目类型交给对应流程：扒剧导入（认不出集号就弹卡）、迭代原稿或锁定稿、原创设定。
- **G6** 锁定稿作为独立产物，强制注入上下文，下游禁止改写；接上本轮起止集和全剧集数。
- **G7** 每个写死的停点都主动弹卡，卡片的回答对接现有的确认和开始接口。第一个要做的是「收稿复述 → 开始分析」。
- **G8** 分析产出里附带结构化的「待定事项」（问题、选项、推荐、依据），用来生成多步卡。
- **G9** 新增「主线方案 2–3 套」停点。
- **G10** 「放开后续停点」动作。
- **G11** 项目级「要求台账」：记录时间、原话、生效起点，之后每次生成都注入。
- **G12** 扒剧在聊天里打通：模式卡、开始卡、进度、交付卡、转迭代卡。
- **G13** 原创在聊天里打通，停点 A 包含男女频。
- **G14** 总编剧回答时注入真实进度，加「不许编时间」的约束。（第一批在做）
- **G15** 后台每个环节做完，主动在对话里发一条白话汇报。
- **G16** 文件卡消息类型。
- **G17** 长消息改为按额度打包处理，处理时显示进度。（第一批在做）

已有、可以直接复用的后端能力：
- 迭代九步状态机，含确认、修改、重新生成、重试
- 国内三道门
- 扒剧的导入、选模式、开始、预计时间、压缩包、确认交付、单集重跑
- 原创全套接口
- 暂停和恢复
- 分片上传
- Word 交付
- 实时推送（SSE）

### 5.2 前端

- **直接复用**：聊天接口层、实时推送客户端（增量、卡片、报告、断线重连）、上传与附件、卡片宿主、项目控制、确认门和叫停条（补上：没有门时按后端给的确认文案画按钮）、文案和错误码映射。
- **需要改**：
  - 聊天逻辑改成打字一律发消息
  - 会话改成一个项目一个会话
  - 消息存储改成完整消息列表，类型有文本、汇报、卡片、进度、文件
  - 输入框和长文折叠
- **新写**：三栏框架、项目侧栏、进度消息、文件卡、右栏项目面板、多步卡。
- **废弃（只移出构建，不删除）**：街景、NPC 办公室画面、立绘、门、对话舞台、旧状态页、旧帮助页、旧聊天视图、表单式新建页、旧店内页、「（小样）」占位文字。
- **源码只留一份**，旧副本归档。

## 六、分期计划

费用是按过去几次前后端包的实际花费估的，只是估算，不是报价。参考：今晚一次线上复现约 $0.23，上一个功能包追加约 $0.35，第一批修复封顶 $0.8。

### 第一期：聊天页 + 迭代流程跑通（国外迭代国外，含续写特例）

- **范围**：G1–G11、G14–G17，前端三栏聊天页，下线旧入口。
- **验收**：
  - 登录后直接进聊天页
  - 有卡片时打字照样能发出，也有回复
  - 上传原稿后 30 秒内出现复述卡
  - 从分析一路走到交付 Word，全程不离开聊天页
  - 每个停点都有卡片
  - 进度消息实时更新，问「咋样了」的回答和后台真实状态一致
  - 中途加的要求能出现在台账里，并体现在后续产物中
  - 续写场景中，锁定稿一字不动
- **费用估算**：$0.8–1.5，按 $1.5 封顶。

### 第二期：扒剧、原创、国内迭代国外

- **范围**：G12、G13、国内三道门和四级诊断；扒剧完成后转迭代。
- **验收**：扒剧能完成选集号 → 选模式 → 开始 → 交付 → 转迭代；原创能走到停点 A、细纲批次、前 3 集；国内迭代能依次过三道门。
- **费用估算**：$0.6–1.2，按 $1.2 封顶。

### 第三期：好用

- **范围**：版本对比、定稿锁定、整批操作、选句批注、干活动效、项目面板增强、单独跟某个角色聊（待定）。
- **验收**：能并排看两个版本的差异；锁定后的稿子不能再改；选中一句话写意见后，只改那一处。
- **费用估算**：$0.8–1.5，按 $1.5 封顶。

## 七、验收流程

1. 前后端每做完一包，先在测试站自测，再由产品经理验收。
2. 产品经理用专用测试账号，以自动化浏览器在正式站把四类流程从头到尾走一遍，每一步截图，并记录网络请求和控制台报错。会花钱的「开始生成」按钮只在已获批的预算内点。
3. 截图、问题清单和费用一起整理好，确认都通过后才请 ayin 来试。后端说「已实现」不算通过。
4. 日常只测改动的部分；每次上线前做一次全量测试。

## 八、风险与红线

- **费用**：每期按上限封顶，超了就停下来报告。花钱、删文件、对外发消息，都必须先经 ayin 批准。
- **用户页面不露底**：页面、接口返回、报错、导出文件中都不能出现模型名、线路名、token 数、提示词或规范原文。只有后台可见。上线前做一次全站扫描。
- **内容长度**：任何内容不许缩短，超长只能拆分；除剧本正文外，单份输出不超过 5 万字。
- **旧代码**：只移出构建，不删除，删除要等 ayin 批准。
- **数据**：不追溯改动老项目；ayin 的真实项目不拿来做测试。
- **速度**：不能让用户干等。任何状态都必须让她看得到「正在做什么」或「错在哪、怎么重试」。
- **已知风险**：
  - 长任务调用可能超时或返回空，需要切分成小块调用，并自动换同类模型。
  - 第一期改动面大，要防止改坏已经能跑的迭代九步。

## 九、需要 ayin 拍板的事项

1. 入口的「新项目还是之前的项目」和「选四类」两张卡，是否合成一张？（她实际使用时就是合在一张里的）
2. 是否保留单独跟扒剧小能手、审稿官等角色聊天？（建议第一期只跟总编剧聊，其他角色的汇报插进同一条对话里）
3. 旧代码怎么处理：只移出、全部删除，还是保留旧详情页作为「高级视图」？
4. 「开始生成」确认卡要不要每次都弹？还是只在预计较大的时候才弹？
5. 三期的顺序和费用上限是否认可？
6. 单独的「花钱」停点在网站上如何呈现？给外部用户使用时，是否要显示额度？
