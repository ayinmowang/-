## R2 生产架构部署说明（Node.js / Next.js 16.4.6 + Nginx + Cloudflare）

对应配置模板位于仓库 `剧本工作台/deploy/`：
- `deploy/nginx-studio-workbench.conf`
- `deploy/studio-workbench.service`
- `deploy/env.production.example`

### 1. 运行时与 `ffmpeg` 依赖校验

- **Node.js 版本**：`next@16.4.6` 强制要求 **Node.js `>=20.9.0`**（上线前在宿主机执行 `node -v` 校验）。
- **`ffmpeg` 解析优先级（`lib/video-compress.ts`）**：
  1. `STUDIO_FFMPEG_PATH`（推荐 Linux 生产安装系统 `ffmpeg`：`apt-get update && apt-get install -y ffmpeg`，并设置 `STUDIO_FFMPEG_PATH=/usr/bin/ffmpeg`）；
  2. 项目依赖内嵌的 `ffmpeg-static`（`next.config.mjs` 已配置 `serverExternalPackages: ['ffmpeg-static']`，防止 Next.js 打包破坏二进制路径解析）；
  3. 系统 `PATH` 中的 `ffmpeg` / `ffmpeg.exe`。
- **部署后必验命令**：
  ```bash
  node -v                         # 必须 >= 20.9.0
  ffmpeg -version                 # 若用系统 ffmpeg
  node -e "import('ffmpeg-static').then(m => console.log(m.default))"
  ```
- **原片无损与轻量化分离原则**：
  - `.data/buckets/` 永远保存 **100% 无损原始上传文件**（供用户下载与 `transfer_iteration` 复用）。
  - 仅在非严格原生模式（`STUDIO_STRICT_NATIVE_GEMINI !== '1'`）送入多模态 LLM 前，按 `STUDIO_FFMPEG_CONCURRENCY`（默认 `2`，上限 `4`）生成轻量化缓存至 `.data/transcode-cache/<sha256>.llm.mp4`（竖屏短边 `480px`、`fps=4/6`、`aac 32k`、`<= 4.5 MB`；超长单集二次压缩至 `360px/2fps`）。
  - 若环境变量设置了 `STUDIO_STRICT_NATIVE_GEMINI=1`，**严格绕过压缩**，直接发送原始字节。

### 2. Nginx 与 Cloudflare 网关参数

- **Nginx 反向代理（见 `deploy/nginx-studio-workbench.conf`）**：
  - `client_max_body_size 256m;`（避免 Nginx 默认 `1m` 直接 413 拒收分集视频）；
  - `proxy_request_buffering off;` 与 `proxy_buffering off;`（上传流式直通 Node 落盘，响应/轮询不积压）；
  - `proxy_read_timeout 180s; proxy_send_timeout 180s; proxy_connect_timeout 15s;`。
- **Cloudflare 边缘限制**：
  - Cloudflare Free/Pro 单次请求体上限为 `100 MB`、源站等待超时为 **`100s`（`HTTP 524`）**。
  - 若分集视频单集超过 100 MB，需走直连/分片或绕过橙云；常规 5–30 MB 分集视频经异步提交（`<1s` 返回）+ 前端 `2.5s` 轮询与服务端预压缩（`< 4.5 MB`）+ `/v1beta` SSE 直连，彻底消除 524/504 网关超时。

### 3. 单进程异步任务、断点持久化与磁盘清理

- **单进程约束**：当前持久化存储 `globalThis.__STUDIO_PERSISTENT_STORE__`、项目写锁 `withProjectLock` 与异步任务注册表 `globalThis.__STUDIO_TRANSCRIBE_JOBS__` 均为单进程内存状态，**生产环境 PM2 / systemd 必须保持单 worker（`instances: 1`）**。
- **断点与磁盘维护**：
  - `.data/transcribe-checkpoints/` 保存已通过校验的分集断点（权限 `0700/0600`，仅服务端读取，绝不返回客户端），整批交付后自动清理；部分集数失败时保留断点，前端点「继续断点续跑」可跳过已完成集数。
  - `.data/transcode-cache/` 为可再生缓存，建议每周清理超过 7 天的过期转码缓存（如 `find .data/transcode-cache -type f -mtime +7 -delete`），**切勿删除 `.data/buckets/`**。

### 4. 更新后的离线校验命令与 `ROUTE_SHA` 契约

- 每次修改 `app/api/studio/route.ts` 后，**必须同步更新 `scripts/recover-saved-transcribe.mjs` 中的 `ROUTE_SHA`**（SHA-256 必须与 `app/api/studio/route.ts` 字节一致），否则 `tests/transcribe-saved-recovery.mjs` 会拒绝通过。
- 全量离线验收命令（共 30 套，含 `tests/step5-production-arch.mjs` 与 `--experimental-strip-types` 解析边界测试，需先通过 `npx tsc --noEmit` 与 `npm run build`）：
  - `npx tsc --noEmit && npm run build`
  - 运行 `tests/` 下全部第 3–5 步离线测试及 `node --experimental-strip-types tests/step3-c3-parse-boundaries.mjs`、`node tests/step5-production-arch.mjs`（以及按需设 `STUDIO_LLM_FIXTURE=1` 校验 fixture 路径）。
