# 页面与交互审查记录

## 设计方向

产品是总编剧与创作者反复协作的工作台。首要动作是交材料、说要求并核对总编剧复述；界面保持安静、易扫描的编辑室气质。左侧找项目，中间读对话与拍板，右侧查素材和要求。羽毛标记是轻量的角色识别元素。沿用现有绿色与纸张色系、Lucide 图标、三栏响应式结构，不新增视觉依赖。

目标视口：390×844、917×893、1440×900。每个视口均需检查首页选流程、建档弹窗、扒剧集号卡、项目会话、右侧项目资料。重点看长文件名换行、移动端键盘与底部输入区、键盘焦点和状态提示。

## 已修问题

| 问题 | 处理 |
| --- | --- |
| 首页已经选择扒剧，建档仍重复选择流程 | 建档只显示已选流程，保留原决定 |
| 建档要求填写“预计总集数” | 删除该输入；未确认时明确显示“待确认” |
| 开头说明已写集数，之后仍追问 | 从明确表达中提取并记入项目；完整原话也入要求台账 |
| 扒剧每上传一个文件都弹“第几集” | 明确文件名自动识别；其余只在对话卡片补录 |
| 确认卡仍像重复选择创作方向 | 改为核对任务复述和素材数量，提供补充入口 |
| 输入框焦点不明显、动效未尊重减少动态效果 | 增加可见键盘焦点及减少动态效果规则 |

## 内容状态与后续验证

| 状态 | 当前反馈与可继续动作 |
| --- | --- |
| 加载 | 项目侧栏显示正在打开工作区；待在登录态检查布局稳定性 |
| 空 | 项目列表和素材面板提示建立项目或添加素材 |
| 错误 | 显示具体错误与重试路径；扒剧重复集号会要求核对 |
| 部分信息 | 集数未定显示待确认，缺集号显示补录卡，仍可继续发素材 |
| 成功 | 建档、上传、集号保存有消息或提示；连接后进入确认卡 |
| 权限 | 未登录时显示登录入口；私有站须由有权限的用户进入 |

代码通过 TypeScript 检查和生产构建。由于审查用浏览器停在私有站登录页，本轮没有取得新版登录态下的完整渲染截图，也没有假称移动端与四类流程已通过。后续由有权限的协作者在上述视口实际操作并记录截图、键盘路径、长文与错误态，再进行视觉收尾。

## 2026-11-17 交互复查

本轮按《界面验收契约》复查了源码与此前 917×893 的建档截图，修复以下可确定的问题：

- 首页不再暗中预选「国外迭代国外」；流程卡有可读的选中状态，未选择就尝试建档时给出明确提示。
- 仅拖入素材也能进入建档，不强制先写文字；模态框保留已选流程和排队素材。
- 上传显示当前文件与总数。中途失败时项目仍保留，剩余文件留在输入区供重试，不再误报「建档失败」。
- 移动窄屏打开项目时，资料面板默认收起，不遮挡对话；用户仍可从顶部按钮打开。
- 确认卡准确称为「核对建档信息」，不会把静态整理说成已完成 AI 材料复述；正式复述留给创作服务。
- 扒剧已识别的集号可在素材面板纠正；超出总集数的集号会阻止连接并给出修正入口。
- 发送框有可读标签，成功与上传过程有状态提示，弹层支持 Escape，减少动态效果设置保持生效。

本地预览中继返回不可用，私有线上站在审查用浏览器中要求登录，故 390×844、1440×900 的实际渲染、键盘全路径和生产登录态下的内容状态仍标记为**未测试**；不能以源码检查代替截图验收。
